# QA Quiz — Roadmap розвитку продукту

> Цей документ самодостатній: його можна завантажити у будь-який AI-агент (Claude Code, Cursor, Copilot Workspace тощо) і почати реалізацію будь-якої фічі без додаткового контексту. Розділ «Контекст проєкту» описує архітектуру, розділ «Конвенції» — обов'язкові правила, далі — 10 фіч із детальними специфікаціями.

---

## Контекст проєкту

**QA Quiz** — статичний веб-застосунок (PWA) для підготовки до технічних співбесід QA-інженера. 654 питання у 8 темах, двомовний (українська/англійська), хоститься на GitHub Pages. **Без бекенду, без білд-степу, без фреймворків** — vanilla JS/HTML/CSS.

### Структура файлів

```
├── index.html   — вся розмітка (екрани: start/quiz/results + 2 модалки)
├── style.css    — стилі, тема "CI Console" (дизайн-токени в :root)
├── quiz.js      — ВЕСЬ код: банк питань (654 шт.) + логіка (~1400 рядків)
├── sw.js        — service worker: network-first для app shell, cache qa-quiz-v2
├── manifest.webmanifest, icons/ — PWA
├── tools/
│   ├── apply-translations.mjs   — вставка en-перекладів у банк питань
│   ├── translations/*.json      — переклади по темах
│   ├── generate-pwa-icons.mjs
│   └── audit-answer-bias.mjs
└── README.md
```

### Дизайн-система: "CI Console"

Інтерфейс стилізовано під вивід тест-раннера в терміналі:
- Темна тема: фон `#0C0F14`, поверхні `#12161D`/`#171C24`, текст `#E4E1D8`
- Акцент — амбер `#E8A33D`; семантика: pass `#4FA872`, fail `#D9645A`
- Шрифт всюди моноширинний: `'JetBrains Mono', ui-monospace` (Google Fonts)
- Мова UI: теми = spec-файли (`selenide.spec`, статуси `PASS`/`FAIL`), режими = команди (`run --mock`, `rerun --failed`), кнопки = `$ команда →`, дашборд-хедер = термінальний prompt `qa@quiz:~$`
- **Будь-яка нова фіча має говорити цією ж мовою** (наприклад, таймер — це duration тесту, челендж — це `diff` двох прогонів)

### Модель даних (quiz.js)

```js
const TOPICS = {
  selenide: {            // 8 ключів: selenide, restassured, qaautomation,
    label: 'Selenide',   //   javacore, playwright, sysdesign, aiqa, qabasics
    en: { label: '...' },     // опційний en-лейбл (є у sysdesign, aiqa, qabasics)
    badge: '...', desc: '...', code: [...],   // legacy, майже не використовуються
    bank: [
      // одне питання = один рядок:
      {q:'Питання?', o:['A','B','C','D'], c:1, e:'Пояснення.',
       en:{q:'Question?', o:['A','B','C','D'], e:'Explanation.'}},
    ]
  }, ...
};
const SPEC_NAMES = { selenide: 'selenide.spec', ... }; // тема → ім'я spec-файлу
```

`c` — індекс правильної відповіді в оригінальному масиві `o`. Кількість питань: selenide 107, qaautomation 105, restassured 98, playwright 93, javacore 92, sysdesign 59, qabasics 55, aiqa 45.

### Ключові функції (quiz.js)

| Функція | Роль |
|---|---|
| `buildTopicCards()` | рендерить дашборд (топбар статистики, ci-action кнопки, spec-list) |
| `openCountModal(topicKey)` → `startQuiz(topicKey, count)` → `initQuiz()` | старт квізу; `topicKey` = тема / `'mock'` / `'mistakes'` |
| `renderQuestion()` | рендерить питання: spec-хедер, `it('...')`, варіанти-чекбокси `[ ] A` |
| `selectAnswer(btn)` → `submitAnswer()` | двофазна відповідь: вибір → підтвердження кнопкою `$ відповісти` |
| `showResults(finishedEarly)` | екран результатів: бейдж `getResultBadge(pct)`, run-summary, `renderWrongList()` |
| `goHome()` | повернення на дашборд |
| `shuffle(arr)` | Fisher-Yates на `Math.random()` (питання + варіанти) |
| `updateMistakeBank(topicKey, idx, isCorrect)` | банк помилок: помилка → додати; 2 правильні поспіль → видалити |
| `trackEvent(name)` | GoatCounter event (`path: 'pwa/<name>'`) — можна перевикористати для аналітики фіч |

Глобальний стан: `currentTopic, questions, current, correctCount, wrongCount, answered, selectedOptionBtn, currentLabelMap, wrongQuestions, lastResultPct`.

### i18n (обов'язково для всіх нових фіч)

- Словник `I18N = { uk: {...}, en: {...} }` + хелпер `t(key, ...args)` (значення можуть бути функціями для плюралізації)
- Поточна мова — глобальна `lang` (`'uk'`/`'en'`), зберігається в `localStorage['qa_quiz_lang']`
- Хелпери банку: `qText(q)`, `qOption(q, i)`, `qExp(q)`, `topicMeta(topic, field)` — з фолбеком на українську
- Статичні рядки HTML оновлює `applyStaticI18n()`; живе перемикання: `refreshQuestionLanguage()`, `refreshResultsLanguage()`; обробник — `#langBtn`
- **Правило: кожен новий видимий рядок додається в ОБИДВІ мови словника. Жодних хардкодів.**

### localStorage (поточні ключі)

| Ключ | Формат |
|---|---|
| `qa_quiz_stats` | `{ [topicKey]: { best: %, last: %, count: N } }` |
| `qa_quiz_mistakes` | `{ [topicKey]: { [idx]: { correctStreak: N } } }` |
| `qa_quiz_lang` | `'uk'` \| `'en'` |
| `qa_quiz_pwa_*` | службові PWA-мітки |

### Верифікація (після кожної зміни)

```bash
node --check quiz.js         # синтаксис
npx serve . -l 8080          # локальний сервер → http://localhost:8080
```
Перевіряти в браузері: обидві мови, мобільний в'юпорт (375px), консоль без помилок. Якщо додаєш нові файли — включи їх у `APP_SHELL` у sw.js.

## Конвенції для реалізації (читати перед кожною фічею)

1. **i18n**: всі нові рядки → у словник `I18N` (uk + en), рендер через `t()`.
2. **Стиль**: CI Console естетика; нові UI-елементи використовують наявні CSS-токени (`--accent`, `--correct`, `--danger`, `--bg2`, `--border`).
3. **Без залежностей**: жодних npm-пакетів у рантаймі, жодного білд-степу. Vanilla JS.
4. **localStorage**: нові ключі з префіксом `qa_quiz_`, читання завжди у `try/catch` (див. `getStats()`).
5. **Аналітика**: значущі дії нової фічі трекати через `trackEvent('<feature>_<action>')`.
6. **SW**: нові статичні файли → у `APP_SHELL` (sw.js). Ім'я кешу бампати НЕ треба (network-first).
7. **Мобільний**: перевіряти на 375px; медіа-запит `@media (max-width: 700px)` вже існує в style.css.
8. **Коміти**: `feat:`/`fix:`/`docs:` + короткий опис англійською (як в історії репо). Кожна фіча — окрема гілка `feature/<name>`, після завершення — PR у `main`.

## F1. Keyboard-first управління

**Навіщо.** Термінальна естетика передбачає клавіатуру. При проходженні 50–100 питань поспіль кліки мишкою суттєво сповільнюють темп.

**Що зробити.**
- `1`–`4` та `A`–`D` (обидві розкладки) — вибрати варіант відповіді (= клік по option)
- `Enter` або `Space` — підтвердити відповідь / перейти до наступного питання (= клік по `#nextBtn`)
- `F` — фініш (= клік по `#finishBtn`), `L` — перемкнути мову (= клік по `#langBtn`)
- Підказка про хоткеї: рядок дрібним шрифтом під варіантами відповідей у стилі термінального hint: `// keys: 1-4 select · enter submit · f finish` (i18n-рядок!)
- Хоткеї активні лише на екрані квізу (`#quizScreen` видимий) і коли фокус не в текстовому полі (перевіряти `document.activeElement.tagName !== 'TEXTAREA'/'INPUT'`)

**Технічно.** Один `document.addEventListener('keydown', ...)` у quiz.js. Вибір варіанта: `document.querySelectorAll('#optionsContainer .option')[n]?.click()`. Візуальний фідбек вибору вже є (клас `.selected`).

**Acceptance criteria.**
- [ ] Повний квіз можна пройти без жодного кліку мишею
- [ ] Хоткеї не спрацьовують у модалках і на дашборді
- [ ] Хінт відображається обома мовами
- [ ] `trackEvent('keyboard_used')` — один раз за сесію при першому використанні

## F2. Режим "на час" (timed mode)

**Навіщо.** Реальна співбесіда обмежена в часі. Тиск таймера — головне, чого бракує симуляції.

**Що зробити.**
- У модалці вибору кількості питань (`#countModal`) додати перемикач таймера: `⏱ off / 30s / 60s` на питання (за замовчуванням off — нічого не змінюється для поточних користувачів)
- Під час квізу: лічильник у хедері поруч з metaCounter, формат `0:27` (моно, при ≤5с — колір `--danger`)
- Таймаут = автоматично неправильна відповідь: питання летить у `wrongQuestions` + `updateMistakeBank(..., false)`, показується правильна відповідь з поясненням (як при помилці), кнопка `$ наступне`
- В результатах: середній час відповіді (`avg 12s/question`) та кількість таймаутів у run-summary (`timed out: N`)
- Streak-логіка вибору відповіді не змінюється: вибір + підтвердження працюють як зараз, просто з дедлайном

**Технічно.**
- Стан: `timerLimit` (null | 30 | 60), `questionStartTime`, `timerInterval`; масив `answerTimes[]` для avg
- `renderQuestion()`: старт таймера; `submitAnswer()`: стоп + запис часу; таймаут викликає спеціальну гілку `submitAnswer` (винести спільну логіку "показати правильну відповідь" у хелпер)
- Таймер очищати в `goHome()`/`showResults()` (щоб не тікав у фоні)
- i18n: нові рядки (`timed out`, `avg …`) в обидві мови

**Acceptance criteria.**
- [ ] off-режим поводиться на 100% як зараз
- [ ] Таймаут коректно оновлює банк помилок і лічильники
- [ ] Перемикання мови посеред питання не збиває таймер
- [ ] `trackEvent('timed_mode_started')`

## F3. Шерабельний бейдж результату (PNG)

**Навіщо.** Користувачі діляться результатами у LinkedIn/Telegram → органічний ріст. Бейдж у стилі shields.io вже є на екрані результатів — лишилося зробити його картинкою.

**Що зробити.**
- Кнопка `$ share --badge` на екрані результатів (поруч із «Обрати тему»)
- Canvas-генерація PNG (~1200×630, og-image пропорції): темний фон CI-теми, бейдж `qa-quiz | PASSED · A · 92%`, назва теми (spec-файл), кількість питань, дрібно — URL проєкту
- Дії: завантажити PNG (`canvas.toBlob` → `<a download>`) + якщо доступно `navigator.share({files})` — нативний шеринг (мобільні)
- Текст бейджа — мовою інтерфейсу

**Технічно.**
- Все на Canvas API, без бібліотек. Шрифт: `ctx.font = '700 48px "JetBrains Mono", monospace'` (дочекатись `document.fonts.ready`)
- Кольори брати з CSS-токенів (захардкодити hex у конфіг генератора — canvas не читає CSS-змінні напряму)
- Дані: `lastResultPct`, `currentTopic`, done/total — вже в глобальному стані
- `trackEvent('badge_shared')` / `trackEvent('badge_downloaded')`

**Acceptance criteria.**
- [ ] PNG читабельний і брендований (перевірити на ретині — генерувати 2x)
- [ ] Працює офлайн (PWA)
- [ ] Обома мовами
- [ ] Кнопка не показується, якщо `done === 0`

## F4. Челендж-лінк — «кинь виклик другові»

**Навіщо.** Вірусна механіка без бекенду: той самий набір питань у тому ж порядку → чесне порівняння результатів.

**Що зробити.**
- Зробити `shuffle()` детермінованим від seed: додати простий PRNG (mulberry32) і `shuffleSeeded(arr, rng)`; звичайні прогони використовують випадковий seed
- На екрані результатів — кнопка `$ share --challenge`: копіює лінк виду `https://<host>/?challenge=<topicKey>.<seed>.<count>.<pct>`
- При відкритті лінка: банер на дашборді в стилі ci-action: `▸ incoming challenge: selenide.spec — opponent scored 92% [ACCEPT →]`; прийняття запускає квіз з тим самим seed/темою/кількістю
- Після фінішу — порівняння: `you 84% vs opponent 92% — FAILED to beat` / `PASSED — you win` + кнопка створити ре-челендж зі своїм результатом

**Технічно.**
- Seed застосовується і до порядку питань, і до порядку варіантів (обидва shuffle-виклики мають брати той самий rng-потік)
- Парсинг `location.search` при ініціалізації; валідувати topicKey проти `TOPICS`, count проти розміру банку
- `pct` суперника — просто число в URL (жодних персональних даних); challenge для `mock` теж підтримати (seed покриває вибірку з загального пулу)
- Стан челенджу зберігати в змінній (не в localStorage) — це одноразовий прогін
- i18n всіх нових рядків; `trackEvent('challenge_created')`, `trackEvent('challenge_accepted')`

**Acceptance criteria.**
- [ ] Два відкриття одного лінка дають ідентичний набір і порядок питань та варіантів
- [ ] Некоректний challenge-параметр тихо ігнорується (звичайний дашборд)
- [ ] Порівняння результатів показується на екрані результатів
- [ ] Ре-челендж генерує лінк з новим pct і тим самим seed

## F5. Spaced repetition з інтервалами + daily streak

**Навіщо.** Поточний банк помилок бінарний («2 правильні поспіль — випало»). Інтервальні повторення повертають питання саме тоді, коли воно майже забуте, — доведено найефективніший метод запам'ятовування.

**Що зробити.**
- Розширити записи `qa_quiz_mistakes`: `{ correctStreak, dueAt (timestamp), intervalDays }`
- Спрощений розклад: помилка → due одразу (interval 0) → правильна відповідь → 1 день → 3 → 7 → 14 → випадає з банку. Нова помилка на будь-якому етапі скидає на 0
- `rerun --failed` показує лише питання з `dueAt <= now`; лічильник на дашборді: `N due now · M scheduled` (i18n, плюралізація через функції словника)
- Daily streak: ключ `qa_quiz_streak` `{ current, best, lastActiveDate (YYYY-MM-DD) }`; будь-яка завершена сесія продовжує серію; пропущений день — скидає. Відображення в топбарі дашборду: `🔥 5-day streak` → у CI-стилі краще `streak: 5d` як четвертий стат
- Міграція: старі записи без `dueAt` вважати due-одразу

**Технічно.**
- Логіка в `updateMistakeBank()` + новий хелпер `getDueMistakes()`; `initQuiz('mistakes')` фільтрує по dueAt
- Дата — `new Date().toISOString().slice(0,10)` для streak; таймзона користувача ок
- Якщо через F7 з'явиться історія сесій — streak рахувати з неї (уникнути подвійного обліку)

**Acceptance criteria.**
- [ ] Питання з майбутнім dueAt не потрапляють у rerun
- [ ] Розклад проходить повний цикл 0→1→3→7→14→out (перевірити, підміняючи dueAt вручну в devtools)
- [ ] Streak переживає перезавантаження і коректно скидається після пропущеного дня
- [ ] Старі дані користувачів мігрують без втрат

## F6. Режим флеш-карток

**Навіщо.** Multiple choice підказує відповідь; на співбесіді варіантів немає. Активне пригадування (сказати вголос → перевірити) тренує саме те, що треба.

**Що зробити.**
- Новий режим у модалці кількості питань або окрема команда на дашборді: `run --flashcards <topic>`
- Екран: питання (той самий spec-стиль `it('...')`) без варіантів → кнопка `$ reveal` → показується правильна відповідь (`q.o[q.c]`) + пояснення `q.e` → дві кнопки самооцінки: `[ knew it ]` (зелена) / `[ didn't know ]` (червона)
- «didn't know» → `updateMistakeBank(topicKey, idx, false)`; «knew it» → `(…, true)` — інтеграція з банком помилок (і з F5, якщо реалізована)
- Результати: `recalled X/Y` замість passed/failed; без медаль-бейджа або з ним — на розсуд
- Прогрес-бар і лічильник у хедері працюють як у квізі

**Технічно.**
- Переважно нова гілка в `renderQuestion()`/`submitAnswer()` або окремі функції `renderFlashcard()`/`gradeFlashcard(knew)`; режим зберігати у змінній `quizMode: 'quiz' | 'flashcards'`
- `initQuiz` не змінюється (той самий вибір питань), рендер інший
- i18n: reveal / knew it / didn't know / recalled — обидві мови
- Хоткеї (після F1): `Space` = reveal, `1`/`2` = knew/didn't know

**Acceptance criteria.**
- [ ] Повний цикл: питання → reveal → самооцінка → наступне → результати
- [ ] «didn't know» додає питання в банк помилок
- [ ] Живе перемикання мови працює і до, і після reveal

## F7. Історія прогресу + export/import

**Навіщо.** Зараз зберігається лише best/last/count — не видно динаміки. Плюс `localStorage` губиться при чищенні браузера, що боляче для PWA-користувачів.

**Що зробити.**
- Новий ключ `qa_quiz_history`: масив записів `{ date (ISO), topicKey, mode, pct, done, total, avgTime? }`, запис у `showResults()`; ліміт ~500 записів (FIFO)
- На дашборді: клік по spec-рядку теми з зажатим модифікатором або окрема іконка → міні-екран/секція історії теми: список останніх прогонів + ASCII-подібний спарклайн тренду у CI-стилі (можна простими div-барами)
- Тренд-індикатор у spec-рядку: `↗` / `→` / `↘` (порівняння середнього останніх 3 прогонів з попередніми 3)
- Export: кнопка на дашборді `$ export --progress` → завантажує JSON з усіма `qa_quiz_*` ключами. Import: `$ import` → file input → валідація структури → запис у localStorage → перерендер. Обидві дії з confirm-повідомленням
- «Readiness score» по темі (опційно): формула на кшталт `best*0.5 + last*0.3 + freshness*0.2`, показувати як `readiness: 87%` в історії теми

**Технічно.**
- Export: `Blob` + `URL.createObjectURL` + `<a download="qa-quiz-progress.json">`; import: `<input type="file">` + `FileReader` + `JSON.parse` у try/catch
- Валідація імпорту: перевірити ключі та типи перед перезаписом; при помилці — нічого не чіпати, показати повідомлення
- i18n всіх рядків; `trackEvent('progress_exported')` / `('progress_imported')`

**Acceptance criteria.**
- [ ] Кожна завершена сесія (включно з mock/mistakes/flashcards) пише запис в історію
- [ ] Export→очистка localStorage→import повністю відновлює стан (стата, помилки, історія, мова)
- [ ] Пошкоджений файл імпорту не ламає наявні дані

## F8. Конструктор кастомного квізу

**Навіщо.** Перед конкретною співбесідою треба міксувати теми під вакансію (наприклад, Selenide + Playwright + REST Assured), а не ганяти по одній.

**Що зробити.**

**Acceptance criteria.**

- [ ] Вибір тем переживає перезавантаження

## F10. Банк питань → JSON + CI-валідація + контриб'юції

**Навіщо.** 654 питання всередині 450-КБ quiz.js — вузьке місце: важко рев'ювити зміни контенту, неможливо приймати PR від спільноти. Винесення у дані + автоматична валідація відкриває контент для контриб'юторів.

**Що зробити.**
- Винести кожен банк у `data/<topicKey>.json`: `{ label, en: {label}, questions: [{q, o, c, e, en}] }`; у quiz.js лишити метадані і завантаження
- Завантаження без білд-степу: `fetch('data/*.json')` при старті (Promise.all, показати мінімальний loading-стан) — АБО згенерований `data/bank.js` одним скриптом-конкатенатором у tools/ (обидва варіанти без фреймворків; fetch чистіший, але потребує оновлення APP_SHELL у sw.js та обробки офлайну — кешування через SW це покриває)
- GitHub Action `.github/workflows/validate-content.yml`: на кожен PR запускає Node-скрипт `tools/validate-bank.mjs`, який перевіряє: рівно 4 варіанти; `c` в межах 0–3; непорожні q/e; en-блок повний (q + 4 o + e); відсутність дублікатів питань у темі; валідний JSON
- `CONTRIBUTING.md`: як додати питання (формат, обидві мови обов'язкові, приклад PR)
- Оновити `tools/apply-translations.mjs` під нову структуру (або deprecated, якщо переклади тепер пишуться прямо в JSON)

**Технічно.**
- Це найінвазивніша зміна — **робити останньою**, окремою гілкою, з повним регрес-проходом
- `initQuiz`/рендер не змінюються, якщо після завантаження зібрати той самий об'єкт `TOPICS`

- Перевірити продуктивність першого завантаження (8 паралельних fetch ~ ок; HTTP/2 на GitHub Pages)

**Acceptance criteria.**

- [ ] CONTRIBUTING.md з прикладом проходить перевірку «новачок зможе додати питання за 10 хвилин»

## Розширення контенту: нові теми банку питань

Формат банку описаний у «Контексті проєкту». Нова тема = новий ключ у `TOPICS` + запис у `SPEC_NAMES` + переклади через `tools/apply-translations.mjs` (або одразу двомовний банк). Після F10 — це один JSON-файл у `data/`. Обидві мови обов'язкові з першого дня.

Правила якості контенту:
- 4 варіанти відповіді, один правильний; дистрактори правдоподібні, не жартівливі
- Позиція правильної відповіді рівномірно розподілена (перевіряти `tools/audit-answer-bias.mjs` — НЕ ставити все у c:0)
- Пояснення `e` — 1–2 речення з практичною деталлю, а не переказ відповіді
- Складність міксувати: ~40% junior, ~40% middle, ~20% senior

### Черга тем (за попитом на співбесідах)

| Пріоритет | Тема | topicKey / spec | Обсяг | Що всередині |
|---|---|---|---|---|
| 1 | SQL та бази даних | `sql` / `sql.spec` | 80–100 | SELECT/JOIN/GROUP BY/HAVING, підзапити, індекси, транзакції, перевірка даних тестувальником |
| 2 | Python для QA | `pythonqa` / `python-qa.spec` | ~100 | основи мови, pytest (fixtures, parametrize, marks), requests, обробка помилок |
| 3 | Cypress | `cypress` / `cypress.spec` | 60–80 | команди, retry-ability, intercept, custom commands, відмінності від Playwright/Selenium |
| 4 | HTTP та мережі | `httpnet` / `http-networks.spec` | ~60 | заголовки, cookies, CORS, TLS, кешування, WebSocket, DevTools Network |
| 5 | Локатори та DOM | `locators` / `locators-dom.spec` | ~50 | XPath vs CSS поглиблено, осі, стійкі локатори, shadow DOM, iframe |
| 6 | Performance testing | `performance` / `performance.spec` | ~50 | JMeter/Gatling/k6, load/stress/spike/soak, latency percentiles, аналіз результатів |
| 7 | Mobile testing | `mobile` / `mobile.spec` | 50–60 | Appium, iOS/Android специфіка, емулятори vs девайси, жести, device farms |
| 8 | JS/TS Core | `jscore` / `js-core.spec` | ~80 | замикання, event loop, промиси, this, масиви/об'єкти — аналог javacore для JS-стеку |
| 9 | Security testing | `security` / `security.spec` | ~50 | OWASP Top 10 детально, OAuth2/JWT/сесії, практичні перевірки для QA |
| 10 | Selenium WebDriver | `selenium` / `selenium.spec` | ~60 | архітектура WebDriver, waits, Grid, виключення — класика без Selenide-обгортки |

Рекомендований старт: **SQL → Python → Cypress** (SQL закриває найбільшу прогалину для всієї аудиторії; Python і Cypress розширюють аудиторію за межі Java+Playwright стеку).
